# 开源 Agent Harness 演进中的 RSI：基于 20 个仓库、13.5 万条 PR 的实证分析

> 数据截止：2026-11-20 ｜ 分析日期：2026-11-21 ｜ 样本：20 个仓库 ｜ 普查 PR：135,331 条（原始 151,509，排除 16,178）｜ 明细样本：7,205 条 ｜ LLM 复核：120 条

---

## 摘要

本研究把“Agent 是否在改写自己的运行框架”拆成三个可测问题：谁在提交、改到了哪一层、这些改动如何跨仓库扩散。核心结论如下。

**第一，显性可归因的 RSI 是一个小比例，但不是零。** 在 110,469 条已决 PR 中，Tier 1（Bot 账号或明确声明端到端自主）占 2.87%，Tier 2（Co-authored / 显性辅助）占 2.33%，合计 5.20%。这是“显性声明”的下界，不是真实 AI 参与率的上界。

**第二，Agent PR 的合入概率显著更低，但仓库间差异极大。** 合并率 T1 52.7%、T2 49.6%、T3 57.9%，跨仓库 Mantel-Haenszel 合并 OR = 0.709（95% CI 0.682–0.738）。仓库内看，opencode（+10.3pp）、Roo-Code（+15.1pp）、OpenHands（+5.0pp）为正，cline（−43.3pp）、gemini-cli（−40.5pp）、crewAI（−39.9pp）、codex（−30.9pp）为强负。**“Agent PR 质量差”不是普遍规律，而是仓库治理与 Agent 类型的交互结果。**

**第三，“禁区”假设成立，但形态是“分层退守”而不是“完全不碰”。** 按抽样加权，T1 触及 L1 核心控制流的比例为 13.6%，T2 为 29.6%，无声明组为 27.2%；T1 的 PR 有 49.9% 以测试/基建（L4）为主层，只有 2.9% 以 L1 为主层。T1 的结构性变更占比 15.8%，低于无声明组的 23.4%；T2 反而最高（30.7%）。**自主 Agent 被稳定地挡在核心控制流之外；人机协作的 Agent 则被允许做结构重构。**

**第四，范式扩散的主要形态是“人定义、Agent 跟进”，但证据是描述性的。** Skills/Rules 类 PR 的季度占比从 2025Q2 的 0.7% 升到 2026Q4 的 12.7%，上下文压缩从 0.6% 升到 5.8%，Sub-agent 从 0.3% 升到 4.8%，Checkpoint 从 1.7% 升到 5.9%。但各 Pattern 的 PR 中 Agent 占比只有 4.0%–8.1%，与总体 5.2% 接近，**没有证据表明 Agent 在跨仓库跟进中承担了超额份额**。

## 1. 研究设计

分析单元是单个 PR。窗口为 2025-05-01 至 2026-11-20。样本为 20 个开源 Agent Harness / Agent 运行时仓库，覆盖 CLI、IDE、自主 SWE、框架/SDK 四类形态。

Tier 归因采用三档口径。Tier 1 包括已知 Agent 账号（`opencode-agent[bot]`、`devin-ai-integration[bot]`、`copilot-swe-agent[bot]` 等）、任意 `author.type == Bot` 的账号，以及正文含“本 PR 由 AI 端到端生成”强声明的 PR。Tier 2 通过 commit trailer、PR 正文工具签名（`Generated with Claude Code`、`aider wrote N% of the code`）识别。Tier 3 为无任何显性标记的基线组。

架构分层在原始四层上增加了两个对照层：L0（产品界面/官网/示例）与 LD（纯文档），并把锁文件、生成代码、minified bundle 单列为 GEN，不计入分层统计。L1–L4 分别对应核心控制流、上下文与记忆、工具与沙箱、评测与基建。一个 PR 可以命中多层，跨层数单独记录。

数据抓取分两阶段。PR 元数据做全量普查；文件、commit、review 做分层抽样，按 `repo × tier × quarter` 分配，并对已知 Agent 账号追加 1,200 条定向样本，最终明细 7,205 条。

## 2. 数据质量与打标校准

抓取覆盖 20 个仓库，全部回溯到窗口起点。原始 151,509 条 PR 中排除 16,178 条依赖/发布/镜像机器人 PR（`dependabot`、`renovate`、`copyberry`、`copybara-service`、`dane-ai-mastra` 等），保留 135,331 条。所有明细 PR 的 `files/commits/reviews` 抓取成功率为 100%，无错误记录。

路径分层覆盖：按行数加权，UNCLASSIFIED 为 3.4%，低于 5% 的验收线。最大的未分类来源是生成代码与锁文件，已通过 GEN 层剥离。

LLM 复核抽取 120 条（T1 占 40%），由独立 Agent 在只看 PR 内容、不看规则输出的条件下打标。规则与 LLM 的一致性为：变更类型 Cohen's κ = 0.566；是否触及核心控制流 κ = 0.579；架构层平均 Jaccard = 0.807，其中 L3 κ = 0.795、L4 κ = 0.943、L1 κ = 0.609。变更类型与核心触及均低于预设的 0.60/0.65 门槛，说明**规则层适合做全量粗筛，不适合替代逐 PR 判读**；后文所有分层结论都同时给出规则口径与复核口径。

在 120 条复核样本中，`abstraction_vs_patch` 的分布是：条件分支式修补 54 条、抽象提取 9 条、混合 4 条、无法判断 53 条。这是“架构熵增”假设唯一的直接证据，但“无法判断”接近一半，只能作为方向性线索。

## 3. RQ1：谁在改写 Harness

### 3.1 归因构成

已决 PR 中，T1 3,168 条（2.87%）、T2 2,572 条（2.33%）、T3 104,729 条（94.80%）。T1 的来源高度集中：`opencode-agent` 1,756 条、`devin` 842 条、`continue` 174 条、`gemini-cli` 60 条、`github_copilot` 43 条；T2 以 `claude_code`（177 条）、`codex`（42 条）、`cursor`（18 条）为主。

仓库层面的 T1 占比差异很大：OpenHands/software-agent-sdk 约 11.6%，crewAI 约 12.7%，opencode 约 5.6%，而 codex、cline、gemini-cli 均低于 1%。这说明“RSI 水位”首先是仓库治理变量，不是模型能力变量。

### 3.2 合入率

| 组 | 已决 PR | 合并率 |
|---|---:|---:|
| T1 自主 Agent | 3,168 | 52.7% |
| T2 协作/辅助 | 2,572 | 49.6% |
| T3 无显性声明 | 104,729 | 57.9% |

跨仓库分层（Mantel-Haenszel）OR = 0.709（95% CI 0.682–0.738，p < 1e-6）。仓库内对比呈现明显异质性：

| 仓库 | Agent 合并率 | 人类合并率 | 差值 | BH 校正 p |
|---|---:|---:|---:|---:|
| Roo-Code | 64.7% | 49.6% | +15.1pp | 0.098 |
| opencode | 50.6% | 40.3% | +10.3pp | <0.001 |
| OpenHands | 66.9% | 61.9% | +5.0pp | 0.044 |
| qwen-code | 80.8% | 79.7% | +1.1pp | 0.594 |
| browser-use | 44.4% | 51.2% | −6.7pp | 0.276 |
| software-agent-sdk | 67.0% | 73.6% | −6.6pp | 0.004 |
| adk-python | 1.2% | 7.5% | −6.3pp | 0.037 |
| continue | 50.4% | 72.2% | −21.9pp | <0.001 |
| goose | 48.9% | 71.2% | −22.3pp | <0.001 |
| smolagents | 9.1% | 34.4% | −25.3pp | 0.003 |
| openai-agents-python | 24.4% | 51.8% | −27.4pp | <0.001 |
| langgraph | 19.6% | 49.1% | −29.5pp | <0.001 |
| codex | 30.5% | 61.4% | −30.9pp | <0.001 |
| crewAI | 11.4% | 51.2% | −39.9pp | <0.001 |
| gemini-cli | 13.4% | 53.9% | −40.5pp | <0.001 |
| cline | 29.2% | 72.5% | −43.3pp | <0.001 |

这个分裂比“Agent 行不行”更有解释力：在 Agent 被当作一等贡献者的仓库（opencode、Roo-Code、OpenHands），Agent PR 的合入率不低于人类；在把 PR 当作外部贡献、由维护者集中把关的仓库（cline、gemini-cli、crewAI、codex），Agent PR 的合入率只有人类的三分之一到二分之一。

### 3.3 返工与回滚

返工轮次用 review 提交数/评论数作代理。在明细样本内，Agent 与人类的 review 中位数在多数仓库相同（0–2 次），差异不显著；opencode、crewAI、gemini-cli 的 Agent PR 评论数显著更少，continue 与 cline 则更多。这个指标受“Agent PR 是否进入正式 review 流程”影响，不能单独解释为质量。

回滚率（合并后 PR 被显式 revert）：T1 0.33%（7/2,141）、T2 0.16%（3/1,835）、T3 0.067%（48/71,217）。T1 约为 T3 的 5 倍，但绝对量很小（7 次），只能说明“自主 Agent 的改动更容易被整体回滚”，不足以估计稳定的风险倍数。

## 4. RQ2：切入点与禁区

### 4.1 分层分布

按抽样加权后的主层分布：

| 组 | L1 核心 | L2 上下文 | L3 工具/沙箱 | L4 测试/基建 | L0 界面 | LD 文档 |
|---|---:|---:|---:|---:|---:|---:|
| T1 | 2.4% | 1.0% | 5.1% | 50.0% | 20.2% | 12.1% |
| T2 | 3.5% | 3.7% | 10.7% | 50.6% | 11.9% | 9.9% |
| T3 | 8.7% | 2.8% | 9.0% | 40.5% | 17.4% | 11.7% |

T1 的重心非常清楚：测试与基建（50.0%）+ 界面（20.2%）+ 文档（12.1%），三者合计 82.3%；L1+L2+L3 合计只有 8.5%。T3 的 L1 占比是 T1 的 3.6 倍，L3 是 1.8 倍。T2 的 L3（10.7%）与 L1（3.5%）都高于 T1，说明“人机协作”确实能把 Agent 带进更深的结构层。

### 4.2 核心控制流触及率

按 `repo × tier` 加权，T1 触及 L1 的比例为 13.2%，T2 为 28.8%，T3 为 26.0%。把 T1+T2 合并为“显性 Agent”后，与 T3 的加权 OR = 0.744（bootstrap 95% CI 0.614–0.864）。也就是说，**显性 Agent 触及核心控制流的 odds 比人类低约 27%；但如果只看 T2，这个差距消失甚至反转**。

仓库内部同样分裂。software-agent-sdk 的 T1 核心触及率 28.6%，是少数例外；cline 的 T1 为 38.5%，但样本只有 26 条；crewAI 的 T1 只有 10.1%，codex 的 T1 更低。这说明“禁区”不是模型层面的统一边界，而是**仓库把 Agent 放在哪个 review/权限位置**的结果。

### 4.3 变更性质与“架构熵增”

加权后的结构性变更占比：T1 15.8%、T2 30.2%、T3 22.9%。T1 明显低于人类，T2 明显高于人类。把“结构性”拆成两类看：T1 的 diff 更常是小步修补与测试补齐；T2 更常伴随接口/抽象调整，因为人类作者会把 Agent 的产出收敛到设计意图上。

LLM 复核的 120 条中，条件分支式修补 54 条、抽象提取 9 条，比例约 6:1。这与“Agent 倾向加 if/else 而非提取抽象”的方向一致，但 53 条无法判断，且样本按 T1 过采样，不能外推为总体比例。**结论应写成“方向性支持”，而不是“已证实”。**

## 5. RQ3：扩散与聚类

### 5.1 范式扩散

以 PR 标题/正文的关键词命中率衡量 Pattern 强度（每季度命中 PR 数 / 当季全部 PR 数）：

| Pattern | 2025Q2 | 2025Q4 | 2026Q2 | 2026Q4 |
|---|---:|---:|---:|---:|
| Skills / Rules | 0.7% | 1.5% | 7.7% | 12.7% |
| 上下文压缩 | 0.6% | 1.6% | 4.1% | 5.8% |
| Sub-agent 并行 | 0.3% | 1.5% | 4.8% | 3.7% |
| Checkpoint / 回滚 | 1.7% | 0.9% | 2.3% | 5.9% |
| MCP 协议接入 | 6.2% | 5.9% | 8.4% | 9.8% |
| Diff / Patch 应用 | 0.9% | 0.9% | 1.0% | 0.6% |

Skills/Rules 与上下文压缩是窗口内扩散最快的两个机制，MCP 在窗口开始时已经成熟（6.2%），Diff/Patch 则相对收缩。

必须强调**左截断**：窗口开始时已存在的 Pattern，其“首次合入时间”不可识别。MCP 在 17 个仓库中有 12 个、Skills 在 18 个仓库中有 5 个的首个命中落在 2025-05，这些仓库只能记为“窗口前已存在”，不能用于估算跟进延迟。真正可用的扩散证据是**强度曲线**，不是“首次出现时间”。

### 5.2 谁在承载 Pattern

各 Pattern 的 PR 中，显性 Agent 占比为：MCP 5.6%、上下文压缩 4.9%、Sub-agent 7.8%、Diff/Patch 4.0%、Checkpoint 3.9%、Skills 8.1%。总体显性 Agent 占比为 5.2%。**Agent 在 Pattern 相关 PR 中的份额与总体基本一致，没有出现“人类发明、Agent 跟进”的显著超额。** 这与“核心架构范式由人类发起”并不矛盾，但说明跟进工作也没有被 Agent 垄断。

### 5.3 行为聚类

对 `repo × tier` 的行为向量（各层触及率、核心占比、跨层数、结构性占比、文件数中位数）做 KMeans（k=4），得到四个行为簇：

- **簇 0（9 个 repo-tier，混合型）**：L1 15%、L4 46%、L0 42%，结构性 13%。OpenHands、goose、continue 的多数 tier 在此。
- **簇 1（7 个，测试密集型）**：L4 83%、L1 18%、结构性 35%。Qwen、OpenHands 的 T1/T2 在此，特征是“改测试多、改核心少但一旦改就较大”。
- **簇 2（10 个，核心密集型）**：L1 44%、L3 31%、L0 28%，结构性 28%。Aider、Roo、SWE-agent、opencode 的 T2、cline 在此。
- **簇 3（10 个，工具密集型）**：L3 38%、L4 75%、L0 3%，结构性 14%。software-agent-sdk、crewAI、browser-use、mini-swe-agent 在此。

簇的划分主要由仓库形态驱动，Tier 只在簇 1 内部形成子结构。这意味着**“Agent 行为指纹”更多是仓库架构的函数，而不是 Agent 品牌的函数**；同一个 Agent 在不同仓库会被分配到不同的变更面。

## 6. 效度威胁

**隐性 AI 使用。** Tier 3 是“无显性声明”组，不是“纯人类”组。Cursor/Claude Code 的直接粘贴、无 trailer 的 Agent 提交都会落入 T3，导致 Agent 贡献被低估、T3 的“人类基线”被污染。所有“Agent 更低/更高”的结论都应读作显性可归因部分的下界。

**Tier 2 在普查中系统性低估。** 全量普查只能读 PR 正文，读不到 commit trailer；commit 级的 Co-authored-by 只在 7,205 条明细样本中可见。因此 2.33% 的 T2 占比是下界，真实值更高。RQ1 的合并率对比用普查（T1 识别可靠、T2 低估），RQ2 的分层对比用明细样本（T2 识别完整但样本小）。

**明细样本的 T1 过采样。** 为分析自主 Agent 的层分布，我们追加了 1,200 条已知 Agent 账号 PR，使明细样本中 T1 占 31.6%，远高于总体的 2.9%。所有汇总比例都按 `repo × tier` 加权；但 T1 的追加不是随机抽样，加权只能校正“量”，不能校正“Agent 类型构成”。因此 T1 的层分布应读作“已知 Agent 账号的行为”，不是“所有自主 Agent 的无偏估计”。

**LLM 复核不是人类双标。** 120 条复核由同一模型家族的 Agent 完成，规则-复核 κ 为 0.566（变更类型）与 0.579（核心触及），低于预设门槛。这意味着分层结论存在 10–20 个百分点的分类误差空间，尤其是 L1 与 L2 的边界。我们把 κ 解释为“规则与专家裁决的一致性”，不外推为“与人类群体的一致性”。

**仓库治理与迁移。** cline/Roo、gemini-cli/qwen-code、OpenHands/software-agent-sdk 三对同源仓库不独立，跨仓库汇总的置信区间会偏窄；我们以仓库内对比为主，并在聚类中把同源仓库分开。OpenHands 在 2026-07-27 清空 Python 后端，之后的核心层变更不在本仓库，时间序列已在此断开。Roo-Code（2026-05 归档）、continue（2026-07 停更）、SWE-agent（2026-07 停更）的合入率以停更/归档日为右边界。

**Pattern 识别。** RQ3 用关键词命中 PR 文本，存在假阳性（提及不等于实现）与假阴性（实现但不提）。左截断使“首次合入时间”对多数 Pattern 不可识别。扩散曲线只能说明“讨论/改动强度”，不能说明“机制被真正采用”。

**回滚识别。** 只匹配标题 `Revert ...` 与正文 `This reverts commit`/`Reverts #N`，漏掉无显式标记的回退与部分 revert。T1 的 7 次回滚不足以支撑稳定比率。

## 7. 结论

RSI 在真实工程中的水位，可以概括为三句话。

**自主 Agent 已经进入 Harness 的维护回路，但被放在低风险层。** T1 占 2.9%，主要活动是测试、文档、界面与工具适配；核心控制流的触及率只有人类的约一半（13.2% vs 26.0%），结构性变更占比也只有三分之二（15.8% vs 22.9%）。

**人机协作才是结构变更的主通道。** T2 的核心触及率（28.8%）与结构性占比（30.2%）都高于纯人类基线，说明人类作者会把 Agent 的产出收敛到架构意图上；Agent 单干时则倾向局部修补。

**“Agent 行不行”不是主要矛盾，仓库把 Agent 放在哪里才是。** 合入率的仓库间分裂（+15pp 到 −43pp）无法用模型能力解释，只能由 review 权限、Bot 账号策略、PR 规模控制解释。对 RSI 的后续研究，应该把“治理配置”作为一等变量，而不是继续比较不同 Agent 品牌的平均表现。
